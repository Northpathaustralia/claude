# ATLAS_DECISIONS — ATLAS ONE

| # | Decision | Why | Revisit when |
|---|---|---|---|
| D1 | **Evolve the existing repo** (NPAOS v0.1) instead of replacing it; NPAOS becomes the NorthPath workspace inside ATLAS ONE, keeping its original routes so deep links from the ops engine still work | Preserves working, tested value; the directive explicitly wants a NorthPath workspace | Never — absorbed |
| D2 | **V1 = client-first Local Edition** (Vite/React, localStorage, BYO provider key in the browser) rather than Next.js+PostgreSQL | Owner is non-technical: zero hosting/env/DB setup; working product in minutes; zero running cost; privacy by architecture. Engines are dependency-injected so the Cloud Edition reuses them unchanged | V3 (Cloud Edition) — triggered by multi-device or team needs |
| D3 | **JavaScript + JSDoc** for new code, not TypeScript | Consistency with the tested existing codebase; engines run under `node --test` with zero extra toolchain | Cloud Edition rewrite is TS per directive preference |
| D4 | **Official `@anthropic-ai/sdk` for Anthropic; fetch/SSE for others** | Anthropic officially supports browser access and is the recommended default; SDK gives typed errors + streaming helpers. Other providers share the OpenAI-compatible wire format | If a provider breaks browser CORS, proxy via Cloud Edition |
| D5 | **Anthropic model mapping:** fast→claude-haiku-4-5, balanced→claude-sonnet-5, max→claude-opus-4-8; Smart/Deep/X10 run on the max tier under the default Balanced profile; **no sampling params ever sent** (current Claude models reject them); adaptive thinking with summarized display on deep modes | Current published catalog/pricing; correctness per provider API rules | New model releases — update `src/atlas/models.js` (single source of truth) |
| D6 | **No faked capabilities:** demonstration replies labelled; image generation, live web, PDF parsing, integrations, computer control all say Planned in the UI | Directive quality rule is absolute | Each item flips to Working only behind a real tested path |
| D7 | **Own safe markdown renderer** (escape-first, fixed tag set) instead of marked/DOMPurify | Model output is untrusted input; escape-first is provably safe and dependency-free; unit-tested against injection | If tables/math needs outgrow it, swap for marked+DOMPurify with the same test suite |
| D8 | **Memory sensitivity screen** (regex classes + explicit confirm) and memory only ever written via explicit user action | Directive: ask permission before sensitive storage; never store silently | Add local classifier when app-lock/encryption lands |
| D9 | **App lock crypto:** PBKDF2-SHA-256 (310k iterations) → AES-GCM-256 via WebCrypto; key lives in memory only; per-write random IV; a passphrase-check sentinel gates unlock; providers mount behind a LockGate so plaintext never renders while locked; explicit typed-ERASE escape hatch for a forgotten passphrase | OWASP-aligned parameters with zero dependencies; honest recovery story (no backdoor) | Raise iterations / switch to Argon2 (WASM) if a dependency is ever justified |
| D10 | **Search providers: Tavily (preferred) + Brave** behind one `searchWeb()` contract; Connected only after a real Test call; CORS failures caught and explained, not guessed | Both have free tiers and simple key auth suited to a keyless-server Local Edition; adapter pattern mirrors AI providers | Add Perplexity/SerpAPI or proxy via Cloud Edition if browser CORS proves unreliable |
| D11 | **Backups export readable (decrypted) JSON even when the lock is on** | The backup is the owner's disaster-recovery path — an encrypted backup + forgotten passphrase would mean total loss; guide tells the owner to store backups privately | Optional passphrase-encrypted export in a later release |
