# Launch Compliance Checklist

Run top-to-bottom before each launch stage. An unchecked box blocks that stage — no exceptions on schedule pressure.

## Stage 1 — Marketing site public (now possible)

- [x] No claim implies access to private data (grep audit run this cycle; register row 3)
- [x] All demo numbers carry visible "Example data" labels in-viewport
- [x] No fabricated testimonials/user counts/results (v1 quotes removed; examples page explains why)
- [x] Every price public; refund policy stated
- [x] Legal pages exist with "draft — pending AU legal review" banners
- [x] Cookie policy matches actual behaviour (zero tracking)
- [x] Founding-offer scarcity is operationally real and its reason published
- [x] "(in formation)" suffix on company name until registered
- [ ] Domain live + privacy@/security@ receiving (external: guide steps 1–3)

## Stage 2 — Taking money (founding seats)

- [ ] Pty Ltd registered; ABN on invoices/terms
- [ ] AU solicitor review of all five legal pages complete; draft banners removed
- [ ] Stripe products match the pricing page exactly; refund policy operationalised in Stripe
- [ ] Consumer-law check: refund wording preserves Australian Consumer Law guarantees (solicitor scope item)
- [ ] Claim register re-audited; every row VERIFIED/QUALIFIED/DEMO ONLY (no OPEN rows)

## Stage 3 — Product beta (data flows begin)

- [ ] Data-deletion callback built and tested end-to-end
- [ ] 30-day disconnect purge implemented with audit certificate
- [ ] Subprocessor list updated to actuals (incl. form backend) on data-processing page
- [ ] Meta App Review approved for requested scopes (or beta opens Studio-mode-only, which requires none)
- [ ] Training opt-out toggle functional, not decorative
- [ ] DSR path tested: access/export/erasure inside 30 days
- [ ] Breach runbook contact tree filled with live addresses; OAIC NDB clocks documented

## Standing (monthly)

- [ ] Stale-claims sweep (beta timeline wording, "in formation", planned-subprocessor list)
- [ ] Copy-lint banned-claims grep on site + new content (pattern in brand/anti-ai-content-checklist.md)
- [ ] Content calendar compliance spot-check: 3 random posts against the register
